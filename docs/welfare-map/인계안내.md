## 작업 목적과 역할

## 실제 진행된 변경

1. 스테이징에서 tocer 플러그인 오류가 나서 `wp-content/plugins/tocer`를 `tocer-disabled`로 변경했습니다. 오류는 `flatten_underscore_array()` 인수 TypeError였습니다. 관리자 로그인은 복구됐지만 근본 원인은 해결하지 않았습니다.
2. 스테이징 Advanced Ads 비활성화, 설정 > 읽기의 검색엔진 노출 차단을 완료했습니다. Site Kit 재연결은 하지 않았습니다.
3. Claude가 만든 `eb-staging-guard.php`를 스테이징 `wp-content/mu-plugins/`에 설치했습니다. 외부 요청 차단 기록을 캡처로 확인했습니다. 시크릿 창의 페이지 소스 검색에서 `gtag/js` 0개, `ga-disable` 1개라는 사용자 확인을 받았습니다.
4. 스테이징 Cloudways Cron Job Management의 Basic / Advanced 목록이 모두 비어 있음을 확인했습니다. 이것은 WordPress 내부 예약 작업이 없다는 뜻은 아닙니다. 보호 파일이 해당 실행을 차단합니다.
5. 복지지도 플러그인 `eb-welfare-map` 1.0.0을 ZIP으로 설치·활성화했습니다. 관리자 미리 보기 상태로 유지하며 방문자 공개는 하지 않았습니다.
6. 스테이징에서 내려받은 최신 `functions.php`를 기준으로 `credentials: 'omit'` 8곳만 `same-origin`으로 수정했습니다. 업로드 후 가평군 서비스 목록이 표시됐다는 사용자 확인을 받았습니다.
7. 위 파일에 기존 복지지도 `patch.json`의 11곳을 순차 적용했습니다. 각 찾기 문자열은 정확히 1번 일치했고, 패치를 역으로 되돌렸을 때 앞선 파일과 일치함을 로컬에서 확인했습니다. `same-origin` 수정도 보존했습니다. 사용자가 스테이징에 덮어쓰기했습니다.
8. 검수 목록 내보내기와 일괄 적용용 MU 플러그인을 추가했습니다. 지역 검수 33건을 스테이징 DB에 반영했고, 상태 화면의 남은 확인 필요 46건을 사용자가 확인했습니다. 기존 가평군 1건과 합쳐 34건을 분류한 상태입니다.

## 지역 검수의 범위와 DB 변경

- 원문 대조: 내보낸 80건의 복지로 공식 페이지를 브라우저로 직접 열어 지원대상·선정기준·근거법령을 확인하고, 불명확한 항목은 서비스 설명과 신청방법도 확인했습니다.
- 결과: 33건 수정 제안, 46건 보류, 가평군 1건 기반영 확인.
- 반영한 값: `ebm_review`의 해당 33개 항목에서 `sc`, `r`, `chk`, `by`, 그리고 근거·주의점을 덧붙인 `memo`. 기존 신청 상태·기간·기타 필드는 보존했습니다. 지도 캐시 갱신을 위해 플러그인의 `ebm_flush_cache()`를 호출했습니다.
- 백업 옵션: `ebmrb_backup_20261018_v1`. 해당 33건의 변경 전 존재 여부·값과 적용 후 값을 담습니다. 전체 DB 백업이 아닙니다.
- `ebm_public`은 변경하지 않았습니다. 정책 원본 목록이나 API 키도 변경하지 않았습니다.
- 적용 도구 화면에 정상 완료 메시지와 되돌리기 버튼이 나타났고, 사용자 확인으로 남은 확인 필요가 46건임을 확인했습니다.
- `review-proposals.json`은 플러그인에 그대로 가져오는 파일이 아닙니다. 내장 33건 도구는 이미 사용했으므로 재실행하지 마세요.
- 보류는 지원 불가를 뜻하지 않습니다. 대상 본문에 지역이 없거나 통합 전후 범위, 공식 설명의 충돌, 기관 보조사업 성격, 오래된 정보 등을 더 확인해야 합니다.
- 지역 분류 검수는 나이·소득·금액·접수기간·사업 존속 전체를 보증하지 않습니다. 영광군 농촌유학처럼 외지인의 전입을 전제로 하거나, 서울 키즈카페처럼 생활권 이용이 포함된 사례는 검수 메모의 조건을 함께 보존하세요.
