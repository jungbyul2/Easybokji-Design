> 단계마다 **먼저 백업 → 바꾸기 → 확인 → 안 되면 되돌리기** 순서입니다.

## 1. 사전 점검·전체 백업

1. **Cloudways 백업**: 운영 앱 → Backup and Restore → 지금 백업(Take Backup Now). 끝난 시각을 적어 둡니다.
2. **운영 `functions.php` 원본 확인**(가장 중요)
   - SFTP로 운영 `wp-content/themes/generatepress_child/functions.php`를 내려받아 보관합니다.
   - 파일 크기가 **850,556바이트**인지 봅니다. 이 저장소에 처음 올린 원본(커밋 `53efb6b`)과 같은 크기입니다.
   - 크기가 다르면 그동안 운영 파일이 바뀐 것입니다. **3단계를 하지 말고** 내려받은 파일을 Claude에게 주세요. 바뀐 부분을 합친 새 파일을 만들어 드립니다.
3. **플러그인 목록 캡처**: 플러그인 화면 전체. 특히 tocer·WP Rocket·Advanced Ads·eb-schedule 켜짐 여부.
4. **운영 글 한 편의 목차(tocer) 캡처**: 반영 후 비교용.
5. **PHP 버전 기록**: 관리자 → 도구 → 사이트 건강 → 정보 → 서버 → PHP 버전(운영·스테이징 둘 다). tocer 판단에 씁니다(9절).

## 2. 복지지도 플러그인 1.0.1 설치 (비공개)

- 파일: `dist/eb-welfare-map-1.0.1.zip` (스테이징에 올린 것과 같은 파일)
- 운영 관리자 → 플러그인 → 새로 추가 → 플러그인 업로드 → 설치 → **활성화**
- 활성화하면 `/welfare-map/` 페이지가 **비공개**로 만들어지고, 공개 설정은 꺼져 있습니다(관리자만 보임). 홈·메뉴 진입점도 방문자에게는 안 보입니다.
- **확인**:
  - 관리자 왼쪽 메뉴에 '복지지도'가 생김
  - 로그아웃(시크릿 창) 상태에서 `/welfare-map/`이 404
- **되돌리기**: 플러그인 비활성화 → 삭제

## 3. 테마 `functions.php` 교체

- 파일: 저장소 `generatepress_child/functions.php`(852,797바이트, md5 `3866e221973bc111453b2bf110443c18`)
  - 운영 주소(easybokji.com)가 그대로 들어 있습니다.
  - **스테이징에서 내려받은 파일은 쓰지 마세요.** 스테이징 주소가 7곳 들어 있습니다.
- 원본(`53efb6b`)과의 차이는 2가지뿐입니다(36줄 추가, 11줄 변경).
  1. 같은 사이트 데이터 요청 8곳 `credentials: 'omit'` → `'same-origin'`
     - 운영에는 비밀번호 보호가 없어 동작은 그대로입니다.
  2. 복지지도 연결 11곳
     - 홈 '지도로 찾기', 메뉴 항목, 맞춤 찾기의 '지역은 가장 나중에 고른 것 하나로'는 플러그인이 공개 상태일 때만 동작합니다(코드 확인: `ebm_can_view()`). 공개 전 방문자 화면에는 나타나지 않습니다.
     - **공개 전에도 바뀌는 것은 휴대폰 메뉴 도구 아이콘 2개뿐**입니다(우리 동네 복지 기관: 지도 → 핀, 주소 찾기: 핀 → 집).
     - 복지로 자료를 받을 때 사업 ID·수정일·지원 주기 칸을 더 저장합니다(화면 변화 없음).
- **목차 영향 없음**: 바뀐 곳은 48·54·55·56·59·68번 절입니다. 목차·글 페이지 코드(15·38·60·61번 절)는 바뀌지 않았습니다(줄 단위 대조).
- 방법: SFTP로 덮어쓰기(테마 편집기는 쓰지 않음, 파일이 커서 저장 중 오류 위험)
- 올린 직후 관리자로 사이트를 한 번 엽니다. CSS가 다시 만들어지고 WP Rocket 캐시가 자동으로 비워집니다.
- **확인**(로그아웃 상태 시크릿 창):
  - 홈이 정상으로 보임
  - 맞춤 찾기(`/find/`)에서 경기도 가평군을 고르면 지역 서비스 목록이 나옴
  - 휴대폰 메뉴가 열림
  - 글 한 편의 목차가 1단계 캡처와 같음
- **되돌리기**: 1단계에서 내려받은 원본 `functions.php`로 다시 덮어쓰기

## 4. 검수 52건 반영

### 4-1. 검수 묶음 51건

- 관리자 → 복지지도 → **검수 묶음**
- 맨 위 숫자가 **'적용할 것 51건 · 이미 적용됨 0건'**인지 확인합니다.
  - 숫자가 다르면 적용하지 말고 화면을 캡처해 주세요.
  - 운영 자료에 없는 사업은 '자료에 없음'으로 건너뛰므로, 몇 건 적을 수는 있습니다.
- 확인란 체크 → '이전 값을 백업하고 51건 적용'
- **되돌리기**: 같은 화면의 '되돌리기' 버튼

### 4-2. 가평군 1건 (WLF00000942, 묶음에 없음)

- 복지지도 → 검수 → '가평군 중·고등학생 무상교복 지원' 찾기 → 자세히 검수
- 적용 범위 '시·군·구' → 경기도 가평군 → 저장
- 스테이징에서 하신 것과 같은 값입니다.

| 구분 | 건수 | 비고 |
|---|---|---|
| Codex 검수 33건 | 33 | 묶음에 모두 포함, 중복 0 |

## 9. tocer 오류: 원인 확인과 판단

### 지금까지 알려진 것

- **언제·어디서**: 스테이징에서 tocer 플러그인 때문에 관리자 화면이 열리지 않았습니다. 오류는 `flatten_underscore_array()` 인수 TypeError였고, 폴더 이름을 `tocer-disabled`로 바꿔 끈 상태입니다.
- **운영 상태**: 지금 운영에서는 tocer가 정상으로 동작하고 있습니다(글 목차 표시 중).
- **조사 한계**: tocer 플러그인 코드가 저장소에 없어서 오류가 난 함수를 직접 볼 수 없었습니다. 웹 검색에서도 같은 오류 보고는 찾지 못했습니다. → **원인은 아직 확인 필요**

### 가장 가능성 높은 원인 2가지 (추정, 확인 필요)

| 후보 | 근거 | 확인 방법 |
|---|---|---|
| ① 스테이징 복제 때 tocer 설정값이 깨짐 | 'TypeError'는 보통 배열이어야 할 값에 빈 값·문자가 들어갈 때 납니다. Cloudways는 복제할 때 사이트 주소를 바꾸는데, 설정값 안에 주소가 들어 있으면 저장 형식이 깨질 수 있습니다. 이번 복제 때 테마 파일 안의 주소까지 바뀐 것이 확인됐습니다. | 스테이징 tocer 설정 화면에서 '저장'을 한 번 다시 누르면 고쳐지는지 |
| ② PHP 버전 차이 | PHP 8부터 이런 형식 오류가 경고가 아니라 오류로 바뀌었습니다. | 1단계 5번에서 운영·스테이징 PHP 버전 비교 (Cloudways는 서버 단위라 같을 가능성이 높음) |

### 운영 반영 전에 해결해야 하나 → **아니요(막는 조건 아님)**. 다만 아래 2가지는 반영 전에 합니다.

- **이유 1**: 이번 운영 반영은 tocer를 건드리지 않습니다. 바뀌는 테마 코드에 목차 관련 부분이 없습니다(3단계 줄 단위 대조).
- **이유 2**: 운영 tocer는 지금 정상입니다.
- **반영 전에 할 것**
  1. **PHP 버전 비교**(1단계 5번)
     - 운영과 스테이징이 다르면 원인 ②일 가능성이 큽니다.
     - 이 경우 나중에 운영 PHP를 올릴 때 같은 오류가 날 수 있으니, **PHP 업그레이드 전에** tocer를 먼저 해결합니다.
  2. **스테이징 원인 확인**(10분)
     - 스테이징 `tocer-disabled`를 SFTP로 내려받아 Claude에게 주세요(eb-schedule 때처럼). 오류가 난 줄을 찾아 원인과 고치는 방법을 정확히 알려 드립니다.
     - 원인 ①이면 스테이징 설정 재저장만으로 해결되고, 운영에는 할 일이 없습니다.
- **반영 후 확인**: 3단계 확인에서 글 한 편의 목차가 1단계 캡처와 같은지 봅니다. 다르면 3단계 되돌리기를 합니다.
