## 9. tocer 오류: 원인 확인됨 (2026-10-18)

### 원인

- tocer 4.2.3은 실행될 때마다 자기 기본 설정 파일(`default.settings.json`)을 **디스크에서 읽지 않고, 자기 사이트에 HTTP로 요청해서** 받습니다(`config.php` 102줄 → `functions.php` 1137줄 `wp_remote_get`).
- 스테이징은 Cloudways 비밀번호 보호(Password Protection) 때문에 이 요청에 **401 화면(HTML)**이 돌아옵니다.
  - JSON이 아니므로 설정값이 `null`이 되고, `functions.php` 1179줄 `flatten_underscore_array( null )`에서 TypeError가 나 사이트 전체(관리자 포함)가 500 오류가 됩니다.
- **재현**: 시험용 WordPress에 tocer 4.2.3을 설치하고 Basic 인증을 켜니 스테이징과 **같은 오류 문구**로 500. 인증을 끄면 정상(설정 14항목 읽음).
- 처음 추정했던 'PHP 버전 차이'와 '복제 때 설정값 깨짐'은 원인이 아닙니다. 타입이 다른 값을 넣는 오류는 PHP 7.4에서도 같은 TypeError가 납니다.

### 운영에 미치는 영향

- **지금 운영은 정상**입니다. 비밀번호 보호가 없어 요청이 JSON을 받습니다.
- 다만 같은 구조라 **운영도 위험이 있습니다.**
  - 자기 사이트 요청이 JSON이 아닌 화면을 받는 순간(서버 과부하 503, 방화벽·봇 차단 화면, 점검 화면 등) 운영 사이트 전체가 500 오류가 날 수 있습니다.
  - 요청 실패(연결 안 됨)는 빈 값으로 처리돼 괜찮지만, '응답은 왔는데 JSON이 아님'이면 멈춥니다.
- 캐시되지 않은 페이지·관리자·크론마다 자기 사이트 요청이 1번씩 더 나갑니다.

### 해결 (tocer 파일은 고치지 않음)

- **파일**: `server/mu-plugins/eb-tocer-local-settings.php`(SHA256 `91bbf8654e854003e79aeaa33376b8d2806959bd3f0880910dd67f9a1cf0c09b`)
- **동작**: 요청 주소가 '이 사이트의 tocer 폴더 `default.settings.json`'일 때만 서버 디스크의 같은 파일을 바로 돌려줍니다.
  - 파일 내용이 같으니 목차 설정은 바뀌지 않습니다.
  - tocer를 업데이트해도 그대로 유지됩니다.
  - 지우면 원래대로 돌아갑니다.
- **시험**(Basic 인증 켠 상태):
  - 홈 200, 로그인 화면 정상
  - 설정 14항목 정상으로 읽음
  - 자기 사이트 HTTP 요청 0건
  - 파일을 지우면 다시 500 → 이 파일이 해결한 것을 확인

### 운영 반영 전에 해결해야 하나

| 대상 | 판단 |
|---|---|
| 스테이징 | **먼저 적용**. 이 파일을 넣고 tocer를 다시 켜야 글 페이지 목차까지 운영과 같은 조건으로 시험할 수 있음 |

### 스테이징 적용 순서 (운영자, 승인 후)

2. 스테이징 `wp-content/plugins/tocer-disabled` 폴더 이름을 `tocer`로 되돌림
3. 관리자 → 플러그인에서 tocer가 꺼져 있으면 '활성화'
4. 글 한 편을 열어 목차가 나오는지 확인
5. **되돌리기**: 문제가 있으면 폴더 이름을 다시 `tocer-disabled`로 바꾸고 2번 파일을 지움
