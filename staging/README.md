# 스테이징 보호 (eb-staging-guard)

테스트 사이트 `https://wordpress-1073525-6734075.cloudwaysapps.com/`에서만 메일, GA4, 웹 푸시, 예약 작업, 외부 API 호출을 막는 파일입니다.

- 파일: `staging/mu-plugins/eb-staging-guard.php`
- 둘 곳: 스테이징의 `public_html/wp-content/mu-plugins/eb-staging-guard.php`
- 테마 폴더(`generatepress_child`) 밖에 있어서 테마를 운영에 올릴 때 같이 가지 않습니다.
- 실수로 운영에 올라가도 사이트 주소에 `easybokji.com`이 있으면 아무 일도 하지 않습니다(시험으로 확인).

## 막는 것

| 항목 | 방법 | 화면에 보이는 결과 |
|---|---|---|
| 메일 | `wp_mail`을 보내지 않고 성공으로 응답 | 폼 완료 화면은 그대로. 기록에 받는 주소 도메인·제목만 남음 |
| GA4 | 테마 30번 추적 코드를 빼고 구글 공식 끄기 신호(`ga-disable`)를 넣음. 다른 플러그인이 넣은 구글 태그 파일도 뺌 | 통계에 스테이징 방문이 섞이지 않음 |
| 웹 푸시 | `ebs_push_off`를 켠 값으로 보이게 함. 예약 작업·외부 요청도 막아 발송 경로 차단 | 알림 종 버튼이 안 보임 |
| 예약 작업 | WP-Cron 실행 목록을 늘 비움. Action Scheduler도 멈춤 | 등록된 작업은 그대로 보이고 실행만 안 됨 |
| 외부 API | WordPress HTTP 요청 중 허용 목록 밖은 막음 | 테마는 DB에 저장된 마지막 데이터로 화면을 그림 |

외부 요청 허용 목록:
- 이 사이트 자신
- `api.wordpress.org`, `downloads.wordpress.org`
- `www.youtube.com`의 `/oembed`만: 키가 필요 없고, 막으면 영상 출처 줄이 비어 운영과 화면이 달라짐

| 기능 | 실패할 때 동작 |
|---|---|

## 복지지도를 넣을 때 고려한 점 (설치는 아직 안 함)

- 서버에서 외부 API를 부르면 막히므로, 복지지도도 **저장된 데이터로 그리는지** 시험할 수 있습니다. 무엇을 부르려 했는지는 도구 > 스테이징 보호의 기록에 주소(인증키 등 `?` 뒤는 빼고)로 남습니다.
- 데이터를 처음 채울 때는 API로 받지 말고 **운영 DB나 내보낸 파일로 가져오는 방법**을 먼저 씁니다. 꼭 받아야 하면 승인을 받은 뒤 그 주소만 허용 목록에 잠깐 더합니다.
- 지도 화면(카카오·네이버 지도 등)은 방문자 브라우저가 직접 불러오므로 이 파일과 상관이 없습니다. 지도 서비스 관리 화면에 스테이징 주소를 등록해야 할 수 있습니다(외부 서비스 설정 변경이라 운영자가 직접). 어떤 지도를 쓰는지는 **확인 필요**.

## 알아 둘 것

- PHP `curl`로 직접 보내는 요청은 막지 못합니다. 웹 푸시 발송 방식은 eb-schedule 플러그인 코드를 보기 전까지 **확인 필요**합니다.
- 스테이징 DB에는 운영 방문자의 알림 구독 정보가 복사돼 있을 수 있습니다. 확인 전에는 스테이징에서 '알림 보내기' 같은 관리자 버튼을 누르지 마세요.
- Password Protection이 켜져 있으면 테마 편집기에서 `functions.php`를 저장할 때 자체 점검이 실패할 수 있습니다. PHP 파일은 SFTP로 바꾸세요. CSS 파일은 편집기로 고쳐도 됩니다.
- `tocer` 플러그인을 꺼 둬서 글 목차 화면이 운영과 다릅니다.
- 스테이징을 운영으로 밀어 올리기(Push to Live) 전에는 이 파일을 지우세요.

## 시험 기록 (2026-10-18)

임시 WordPress(SQLite)에 자식 테마와 이 파일을 넣고 확인했습니다.

- 스테이징 주소일 때:
  - 메일은 보낸 것처럼 처리되고 기록에 남음
  - `apis.data.go.kr`, `www.mohw.go.kr`, `easybokji.com`으로 가는 요청 막힘. 인증키는 기록에 남지 않음
  - 실행할 예약 작업 0개
  - `ebs_push_off` 값이 1
  - 저장된 새 소식이 화면에 나옴
  - 페이지에 `gtag/js`는 없고 `ga-disable` 신호만 있음
- 운영 주소(`easybokji.com`)일 때: GA4 코드가 그대로 나오고, 메일도 보내려고 시도함 → 이 파일이 아무 영향을 주지 않음

## 변경 기록: 맞춤 찾기 내부 요청 credentials (2026-10-18, 스테이징 먼저)

- **증상**: 복지지도 '내 조건으로 더 좁히기' → 맞춤 찾기(경기도 가평군)에서 '지역 서비스를 불러오지 못했어요'.
- **원인**: `functions.php`의 같은 사이트 REST 요청 8곳이 `credentials: 'omit'`이었습니다. 이 설정은 브라우저가 Password Protection(Basic 인증) 정보를 빼고 보내게 해서, 서버가 401(인증 필요)을 돌려줍니다.
- **재현**:
  - 임시 WordPress에 Basic 인증을 걸고 Chromium으로 `/find/?sd=경기도&sg=가평군`을 열었습니다.
  - 고치기 전: `/wp-json/eb/v1/local`과 `/services` 모두 401, 오류 문구 나옴.
  - 고친 뒤: 둘 다 200, 가평군 서비스가 보임.
- **수정**: `{ credentials: 'omit' }` → `{ credentials: 'same-origin' }` (8곳, 모두 `rest_url()`로 만든 이 사이트 주소)

| 위치 | 요청 |
|---|---|
| 48번 홈 찾기 카드 | `finder-data`, `services`, `local` |
| 55번 맞춤 찾기 | `local`, `services` |
| 59번 휴대폰 빠른 찾기 | `local`, `finder-data`, `services` |

- **운영 영향(반영은 승인 후)**:
  - 운영에는 Basic 인증이 없어서 응답이 같습니다.
  - 로그인한 관리자는 쿠키가 함께 가지만, nonce(일회용 보안 값)가 없어 WordPress가 로그인으로 보지 않으므로 응답은 같습니다.
  - Password Protection과 스테이징 보호 파일은 바꾸지 않았습니다.
